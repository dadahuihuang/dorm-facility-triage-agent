## 二、逐用例记录

### TC-01 标准首轮报修

**输入**：`你好！ 5栋三楼305宿舍灯坏了！麻烦快点`

**预期**：不追问，直接出工单；类别 ELEC；置信度 > 90%；地点含 305；自动分诊。

**实际**：

| 字段 | 值 |
|---|---|
| 状态 | success（1 张工单） |
| 设施类别 | ELEC |
| 置信度 | **98.8%** |
| 报修地点 | 5栋三楼305 |
| 派单部门 | 电工班 |
| 要求响应 | 2小时内 |
| 人工复核 | 否 |

**判定**：PASS。语气词"你好/麻烦快点"与标点被清洗，位置实体完整抽取，无重复楼层。

---

### TC-02 多轮追问 + 室内强制房间号

**输入**：
1. `空调不制冷`
2. `在3栋2楼`
3. `201`

**预期**：第 1 轮追问位置；第 2 轮识别为室内设备（空调）**继续追问房间号**；第 3 轮出工单，地点 `3栋2楼201`。

**实际**：

| 轮次 | 状态 | 追问内容（节选） | 已抽取位置 |
|---|---|---|---|
| 1 | ask_for_location | 请提供具体的房间号，比如 302 室 | — |
| 2 | ask_for_location | 请提供具体的房间号，比如 302 室 | 3栋 / 2楼 |
| 3 | success | — | **3栋2楼201** |

第 3 轮工单：HVAC / **99.9%** / 3栋2楼201 / 空调维修组 / 8小时内 / 自动分诊。

**判定**：PASS。这一条是本轮修复的重点（此前"3栋2楼"会被误判为位置完整而直接放行）。

---

### TC-03 多故障多位置拆单（缺房间号先追问）

**输入**：
1. `3栋2楼走廊灯坏了，4栋4楼寝室门锁也打不开了`
2. `402`

**预期**：第 1 轮走廊灯（公区，位置完整）先出单；寝室门锁因缺房间号**必须追问**，不得直接出单；第 2 轮补齐房间号后，两张工单一起出。

**实际**：

| 轮次 | 状态 | 说明 |
|---|---|---|
| 1 | ask_for_location | 播报"其中「3栋2楼走廊」的报修已为您生成工单"，并追问"具体的房间号（如 402 室）"；暂存 1 张待出库工单 |
| 2 | success | **2 张工单**（含第 1 轮挂起的那张） |

| 工单 | 类别 | 置信度 | 地点 | 部门 | SLA | 高危 |
|---|---|---|---|---|---|---|
| 1 | ELEC | 97.5% | 3栋2楼走廊 | 电工班 | 2小时内 | 否 |
| 2 | DOOR | 99.4% | **4栋4楼402** | 综合维修组 | 12小时内 | 否 |

大模型播报：已说明"拆分为 2 张工单，分别派给综合维修组和电工班"。

**判定**：PASS。**关键点：寝室属于室内空间，没有房间号绝不生成工单**；同时不浪费用户已提供的信息，位置完整的那条先落单、后补的那条自动合并。

### TC-04 高危规则兜底

**输入**：`3栋301电线冒烟了，有焦味`

**预期**：跳过自动分诊，亮红色高危警告；状态"需人工复核"；SLA 升级为 15 分钟紧急。

**实际**：

| 字段 | 值 |
|---|---|
| 类别 / 置信度 | ELEC / 89.9% |
| 高危标记 | **是**（命中"冒烟""焦味"） |
| 状态 | **需人工复核** |
| 要求响应 | **15分钟（紧急）** |
| 派单部门 | 电工班 |

播报原文："由于本工单需要人工复核，我们已经将您的报修转交给了人工客服进行进一步确认和加急跟进。"

**判定**：PASS。规则引擎优先级高于模型置信度，安全兜底有效。

### TC-05 意图打断 + 闲聊防污染

**输入**：
1. `马桶堵了`
2. `哎，今天上课太累了`（故意跑题）
3. `1栋2楼走廊厕所`

**预期**：第 1 轮追问位置；第 2 轮不被当成地址，继续追问；第 3 轮识别为公区、生成 WATER 工单，地点 `1栋2楼走廊厕所`。

**实际**：

| 轮次 | 状态 | 说明 |
|---|---|---|
| 1 | ask_for_location | 追问房间号/楼层区域 |
| 2 | ask_for_location | 未被闲聊污染，继续追问位置，故障仍为"马桶堵了" |
| 3 | success | WATER / **94.0%** / **1栋2楼走廊厕所** / 水工班 / 4小时内 |

附加：WATER 类触发外部工具，返回"当前有暴雨预警，请优先处理漏水工单！"。

**判定**：PASS。此前的 bug 是公区"走廊厕所"被丢掉，只剩"1栋2楼"，已修复。

### TC-06 低置信度转人工复核

**输入**：
1. `那个东西有点问题，一直响`
2. `2栋2楼201`

|---|---|
| 类别 / 置信度 | ELEC / **37.0%** |
| 状态 | **需人工复核**（置信度 < 0.6 且 top1-top2 差距不足） |
| 原因 | 系统置信度较低，需进一步确认 |
| 地点 | 2栋2楼201 |

播报原文："您的报修信息已经生成了一份工单，并且已经转交给了人工客服进行进一步的确认和加急跟进。"

**判定**：PASS。文案与系统状态一致（此前会出现"系统说复核、大模型说已派单"的矛盾）。

## 三、本轮修复清单（可作为报告的"改进"素材）

| # | 问题 | 根因 | 修复 |
|---|---|---|---|
| 1 | "1栋2楼走廊厕所"被要求补房间号 | `strong_indoor` 含"马桶"，把公区场景强制成室内 | 私有设备白名单收窄为 空调/床/衣柜/书桌/淋浴/热水器/插座/饮水机/台灯；"马桶"改由公区词判定 |
| 2 | 首句多故障拆不开 | 拆单条件要求 `context` 非空 | 去掉该条件，任一轮都可拆 |
| 3 | 寝室报修缺房间号也出单（**你发现的问题**） | 室内场景判断依赖关键词黑名单，"寝室"被误移出 | 改为按场景判定：`loc_type == "indoor"` 一律要求 3-4 位房间号，与关键词解耦 |
| 3b | 一处完整一处缺信息时，整句卡住或丢单 | 拆单要求所有子句都成功 | 位置完整的先出单并挂起，缺位置的追问，补齐后合并出单 |
| 4 | "1栋2楼走廊厕所"地点丢词 | 区域正则只取第一个匹配 | 追加全部公区关键词（走廊/厕所/洗衣房…） |
| 5 | 门锁"打不开"误判高危 | 高危词库含"打不开/进不去" | 移除二者，改留"反锁/被困/出不去"；SLA 恢复 12 小时 |
| 6 | 大模型仍输出 Emoji | 提示词约束不稳定 | `call_llm` 统一做 Emoji 兜底清洗 |
| 7 | 闲聊时讲笑话 | 系统提示词过弱 | 明确"不提供娱乐内容、只拉回报修" |
| 8 | 需复核却播报"已自动派单" | 播报 Prompt 未感知 `need_human` | 播报加入复核数量 + "人工"关键词兜底 |

## 四、已知局限（可写入报告 5.3 误差分析）

1. **合成数据规律性强**：测试集 Macro F1 达 0.9935，明显高于真实场景预期，主因是模板合成导致训练/测试分布接近。建议在报告中明确说明，并给出真实素材 23 条与合成 2911 条的构成。
2. **单标签模型**：一句多故障依赖 Agent 层按逗号/连词拆单，拆不干净时会漏报（如"灯坏了还漏水"无标点时）。
3. **状态机而非大模型路由**：多轮意图切换靠正则与关键词，极端绕弯表述仍可能误判。
4. **高危规则仍为黑名单**：未覆盖词（如"异味""发烫"）可能漏报，需持续扩充。
